Multimodal Sparse MoE

Separate total capacity, active experts, n-gram storage, and the cost of multimodal inputs.

A large workshop owns many specialist stations. Each job visits a few stations, plus a shared workbench. Buying all the stations determines storage; the route taken by one job determines part of its computation.

Routing selects computation

A router scores experts for a token representation and chooses a small subset. Their outputs are combined with routing weights. A shared expert provides a path used broadly. The selected experts need not have human-assigned specialties such as “math” or “images”; any specialization is learned.

Three different accounting questions

Stored parameters determine how many weight values exist. Active parameters describe the values involved in processing a token under a stated accounting convention. Runtime memory additionally includes activations, KV cache, workspaces and framework overhead. A routed-expert fraction cannot alone recover the active parameter total, because shared and dense components also contribute.

Multimodal inputs still need representations

A vision encoder turns visual input into representations the language model can use. More image patches or video frames can increase sequence length and preprocessing work. Sparse language-model routing does not make the vision encoder, attention or input processing free. Compare workloads with matched image resolution and frame sampling.

Sparse work can have dense systems costs

Experts must reside somewhere or be transferred. Distributed routing can move token activations between devices; skewed routing can overload a few experts. Thus low per-token active capacity is only one part of efficiency. Batch shape, load balance, communication and quantization influence actual throughput.

Worked example

Ten routed selections from 512 available experts is 10 / 512 ≈ 1.95%. This is a routing fraction, not 6 / 125 and not total runtime memory. For a separate storage exercise, 125B + 51B + 4B = 180B values; at two bytes each that is 360 GB in decimal units before additional runtime memory and any separately counted components.
